The idea

The Artwork Contains The Number That Describes Itself.

s = Prefix(H(I(s, n)))

I(s, n) is the image file with signature s painted in and some nonce n tucked away somewhere. H is SHA-256. The goal is a file whose hash starts with the very digits drawn on it.

You cannot compute this. SHA-256 gives you no way to steer the output, so changing one byte reshuffles the whole hash. The only way in is to guess: try a nonce, hash, compare, repeat. Each hex digit you ask for multiplies the expected number of tries by 16. Eight digits means about 4,294,967,296 tries on average. That cost is the point. It is proof of work, painted where you can see it.

Trick 1

Paint Once, Search Somewhere Else.

The obvious approach re-renders the image for every guess: draw a candidate, encode a PNG, hash three megabytes, throw it away. At that rate, four billion guesses would take months.

Instead the signature is painted exactly once and never touched again. The thing that changes is a 16-character counter at the very end of the file, where image viewers never look. The pixels stay fixed and only the tail of the file changes. It is still the same equation, solved in a cheaper order.

Trick 2

Hash 3 MB Once, Then 64 Bytes Per Guess.

SHA-256 eats its input in 64-byte blocks, front to back, carrying a 32-byte internal state from one block to the next. If the first 3,053,504 bytes never change, the state after them never changes either. So the miner hashes those 47,711 blocks one time, saves the state (the midstate), and from then on every guess costs a single block.

It lines up exactly because the signer pads the trailer with dots until the nonce starts on a block boundary. You can see that padding in the file: ::......... nonce=. Those nine dots buy a 47,712× speed-up.

Trick 3

Let The Silicon Do It.

Apple Silicon, like most modern ARM chips, has dedicated SHA-256 instructions. The miner is about 200 lines of C. Its inner loop is four instructions per four rounds, run on all ten cores of an M1 Max:

for (int i = 0; i < 16; i++) {
    uint32x4_t wk = vaddq_u32(m[i & 3], vld1q_u32(K + 4 * i));
    if (i < 12)
        m[i & 3] = vsha256su1q_u32(vsha256su0q_u32(m[i & 3], m[(i + 1) & 3]),
                                   m[(i + 2) & 3], m[(i + 3) & 3]);
    uint32x4_t t = abcd;
    abcd = vsha256hq_u32(abcd, efgh, wk);
    efgh = vsha256h2q_u32(efgh, t, wk);
}

That runs at about 155 million guesses per second. This signature needed 5,681,174,478 of them: about 37 seconds, and a little unlucky (1.3× the average).

Trick 4

The Signature Survives The Act Of Signing.

Which eight digits to paint? Not random ones. fdbf223d is the start of the hash of the original, unsigned artwork. Signing it changes millions of pixels and appends a whole archive, and the hash still starts the same way.

Trick 5

It Is Also A ZIP File That Contains Its Own Source Code.

PNG readers start at the front of a file and stop at the IEND chunk. ZIP readers start at the back and look for the end-of-archive record. So one file can be both, and this one is. Unzip the painting and you get the program that painted it, the miner that searched for it, and a verifier.

      Limits
      
What It Proves, And What It Doesn't.

      

        

          
Proves

          
Someone spent about 232 SHA-256 computations on exactly these bytes. The picture, the metadata and the embedded code are sealed together: change any byte and the claim breaks.

        

        

          
Doesn't prove

          
Who made it. Anyone can take the image, put their own name in, and spend the same 30 seconds. Authorship needs a real signature (Ed25519) or a public timestamp on top.

        

      

      
The proof lives in the exact bytes. Instagram, X and most messengers re-encode images on upload, which strips the archive and breaks the hash. To share the real thing, send the file itself, or a link that serves it untouched, like this page.

Where The Rabbit Hole Goes Next.

      
None of these are built yet. They are the sketches on the studio wall.

      
    
        
  • Paint the block it will land in. Put a future Bitcoin block height on the canvas, then record the file's hash in that exact block. Bitcoin's nLockTime rule guarantees the transaction can't be mined any earlier, and a high fee sent the moment the previous block appears lands it there most of the time.
    • 
        
  • Add an authorship signature. An Ed25519 signature in the metadata, with the public key published elsewhere, closes the gap above.
    • 
        
  • A binary that runs everywhere, inside the painting. Cosmopolitan's "actually portable executables" are single files that run natively on Linux, macOS and Windows. Put the verifier in the ZIP as one, and the picture carries a program any computer can run.
    • 
        
  • A gallery over SSH. ssh ships with macOS, Linux and Windows. One identical command on every machine could open the art, the story and the verifier in a terminal.
